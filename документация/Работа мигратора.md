Теперь важный момент: верни переменную подключения с тестовой `idm_migration_test` обратно на основную `idm`:

```powershell
$env:IDM_DB_CONNECTION="Host=127.0.0.1;Port=5432;Database=idm;Username=idm;Password=idm_password"
```

Если старые тестовые данные нам **не нужны**, я бы пересоздал основную `idm` и сразу прогнал мигратор — тогда с этого коммита мигратор становится единственным источником создания/изменения схемы:

```powershell
podman exec -it idm-postgres psql -U idm -d postgres
```

```sql
DROP DATABASE idm;
CREATE DATABASE idm OWNER idm;
\q
```

Затем:

```powershell
dotnet run --project .\src\Idm.DbMigration\Idm.DbMigration.csproj
```

И тестовую после этого можно удалить:

```powershell
podman exec -it idm-postgres psql -U idm -d postgres
```

```sql
DROP DATABASE idm_migration_test;
\q
```

После этого у нас чистое состояние проекта:

```text
idm
├── 000 migrator bootstrap
└── 001 initial schema

database/migrations/
└── 001_initial_schema.sql
```
