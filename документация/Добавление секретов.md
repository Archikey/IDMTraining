Находясь в корне решения, сначала инициализируй secrets именно для проекта:

```powershell
dotnet user-secrets init --project .\src\Idm.DbMigrator
```

В `.csproj` после этого появится примерно:

```xml
<PropertyGroup>
    <UserSecretsId>...</UserSecretsId>
</PropertyGroup>
```

Сам секрет при этом **не хранится в проекте**.

Теперь записываем connection string:

```powershell
dotnet user-secrets set "ConnectionStrings:Postgres" "Host=localhost;Port=5432;Database=idm;Username=idm;Password=idm_password" --project .\src\Idm.DbMigrator
```

Проверить:

```powershell
dotnet user-secrets list --project .\src\Idm.DbMigrator
```

Увидишь:

```text
ConnectionStrings:Postgres = Host=localhost;...
```

Секрет физически хранится отдельно в профиле твоего Windows-пользователя, а не рядом с исходниками. Поэтому `git add .` его не захватит.

Но теперь интересная часть задания: **как прочитать его из обычного Console Application?**

В ASP.NET Core конфигурация обычно уже подготовлена framework'ом, а у нас `Idm.DbMigrator` — обычная консольная программа. Поэтому тебе потребуется собрать configuration самостоятельно.

Направление такое:

```text
User Secrets
     ↓
IConfiguration
     ↓
ConnectionStrings:Postgres
     ↓
NpgsqlConnection
```

Тебе понадобятся пакеты/пространства имён из семейства:

```text
Microsoft.Extensions.Configuration
Microsoft.Extensions.Configuration.UserSecrets
```

И задача для тебя: найди, как через `ConfigurationBuilder` подключить user secrets и затем получить:

```text
ConnectionStrings:Postgres
```

Если застрянешь именно на синтаксисе `ConfigurationBuilder` — спрашивай, разберём его отдельно.

И ещё важное различие на будущее:

```text
Development:
User Secrets ✅

Production:
User Secrets ❌
Environment variables / Kubernetes Secrets / secret storage
```


# Закрытый вариант


В PowerShell на текущую сессию:

```powershell
$env:IDM_DB_CONNECTION="Host=localhost;Port=5432;Database=idm;Username=idm;Password=idm_password"
```

Проверить:

```powershell
$env:IDM_DB_CONNECTION
```

А стандартный .NET/C# умеет читать environment variables **без дополнительных NuGet-пакетов**:

```csharp
var connectionString =
    Environment.GetEnvironmentVariable("IDM_DB_CONNECTION");
```

Это заодно ближе к тому, как потом будем работать с контейнерами:

```text
Local development
PowerShell environment variable
            ↓
         C# process

Позже Podman
-e IDM_DB_CONNECTION=...
            ↓
         C# container

Позже Kubernetes
Secret
  ↓
environment variable
  ↓
C# process
```
